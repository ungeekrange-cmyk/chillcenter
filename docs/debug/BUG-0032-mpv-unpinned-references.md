# BUG-0032 — Référence de média hors transport épinglé

2026-10-14, candidat source0456474 + régression root. HIGH : le callback principal était limité au transport Rust, mais libmpv pouvait suivre une référence embarquée indépendamment. Cause confirmée : access-references=yes par défaut, aucune désactivation à l'initialisation. Sources primaires : [manuel mpv, access-references](https://mpv.io/manual/stable/#options-access-references), [autoload-files](https://mpv.io/manual/stable/#options-autoload-files), options de mpv0.41 installé (`mpv --no-config --list-options`).

RED réel : média en mémoire `chill-memory://reference-fixture.mp4` contenant une playlist M3U avec seul endpoint HTTP synthétique loopback. Le listener observe une connexion hors transport ; test `media_references_cannot_open_unpinned_http` FAILED : « embedded media reference bypassed the pinned transport ». Aucun réseau extérieur, NAS, clé ou document utilisateur.

Correction au seul responsable : config/load-scripts/ytdl/access-references/autoload-files/osc désactivés avant mpv_initialize ; ces réglages ne sont pas modifiables via les options extra autorisées. Les pistes intégrées restent décodées et les sous-titres externes sont ajoutés explicitement depuis le cache privé validé, pas découverts sur disque par mpv. La lecture suit toujours le callback Rust. Ceci ne prétend pas sandboxer tous les codecs natifs ou prévenir une vulnérabilité de FFmpeg ; le manuel avertit que certaines anciennes implémentations peuvent ignorer access-references. Une preuve adversariale spécifique accompagne les régressions formats.

GREEN réel : `cargo test --offline --locked -p chill-player -- --nocapture` PASS,14 tests, dont le listener adversarial n'observe plus de connexion et les options de sécurité ne peuvent être écrasées. Pistes/seek/fixture MP4 passent. Matrice Tauri après correction et revue sécurité indépendante à rattacher avant livraison. Aucun merge/deploy global tant que cette correction n'est pas vérifiée.
