## Findings

1. **HIGH — A failed profile switch can split the displayed identity from the identity used for writes.** `crates/chill-client/src/ui.rs:451-463` assigns `Connected.active` and the in-memory `last_profiles` entry before `save()` and before the follow-on `view()` requests succeed. If either local persistence or any view request fails, the command returns `Err` without restoring the former profile. The webview error path retains the previous `state.profile_id` and resets the selector to that old value (`ui/connected/app.js:8-11,46`). A later catalogue/preferences/watched/rating command therefore derives profile B in Rust while the interface still presents profile A; a refresh can even render B's catalogue under A's stale selector. This violates the profile isolation/remembering contract and can mutate another profile's personal state. **Required:** make selection transactional: build and validate the prospective view, persist the server-scoped last choice, then commit `active`, or restore both `active` and `last_profiles` on every error. Until resynchronization succeeds, block profile-scoped commands. Add injected save failure and follow-on GET failure tests proving the old identity remains authoritative (or the UI is forced to an identity-neutral state) and that no command can write under the unrendered profile.

2. **HIGH — Mutations queued behind a scan can execute after both client and server have reported timeout.** A completed worker scan submits the full catalogue snapshot as one database-actor job (`crates/chill-server/src/catalog_api.rs:160-164`). All profile/preferences/personal-state calls enqueue closures and invoke `job(store)` even if their oneshot receiver was dropped (`crates/chill-server/src/api.rs:56-74`). The client timeout is 20 seconds (`crates/chill-client/src/lib.rs:26,512-524`) and middleware drops the request at 30 seconds (`crates/chill-server/src/api.rs:149-151`). On the Pi target or a large catalogue, a snapshot can occupy the actor beyond either deadline; queued create/rename/delete/preferences/watched/rating operations then return a timeout to the user but still run later. This permits invisible late deletion or personal-state change and makes retries conflict with work reported as failed. **Required:** keep catalogue preparation outside the interactive actor and reduce the final commit to a bounded transaction, and make queued jobs deadline/cancellation-aware before executing (at minimum skip a job whose response receiver is closed; ensure a started mutation cannot commit after its response contract has expired). Add a deterministic blocked-actor regression: let the request time out, release the actor, and assert the mutation never appears; also prove interactive calls stay responsive during a large scan snapshot.

3. **MEDIUM — The bridge discards typed API error codes, so several actionable states are reported incorrectly.** `json_with_options` drops every non-success response body and preserves only the status (`crates/chill-client/src/lib.rs:564-567`); `UiError` then maps status alone to three generic messages (`crates/chill-client/src/ui.rs:77-101`). Thus `SCAN_ACTIVE` is described as a concurrent edit, `ROOT_REQUIRED`/configuration failures as a bad value or duplicate name, and 503/database failures as HTTPS/certificate failures. The server compounds this by mapping every unrecognized store error, including database I/O failures and missing media, to `400 INVALID_OPERATION` (`crates/chill-server/src/api.rs:56-74`). This does not meet the precise retry/correction state required by US-001-AC-03/US-004-AC-04 and leaves the new personal/scan UI unable to choose a safe recovery. **Required:** use a typed server/domain error enum, return correct 404/409/422/503 classes, read the bounded JSON error envelope on non-success responses, carry a stable error `code` through `UiError`, and render operation-specific recovery without exposing sensitive detail. Cover at least scan-active, root-required, CAS conflict, missing profile/media, busy/database-offline, and invalid address.

4. **MEDIUM — Automatic post-expiry key replacement is recorded but not visible to the user.** The verifier appends `KeyReplacedAfterKnownExpiry` and changes the pin (`crates/chill-client/src/lib.rs:456-473`), but `finish_connect` returns an ordinary connected view and never exposes the event (`crates/chill-client/src/ui.rs:308-390`); the UI has no rendering path for it. ADR-0005 explicitly requires this accepted-risk fallback to produce a visible event, and US-005-AC-03 requires the automatic acceptance to be signaled. A record hidden inside `client.json` is not a visible signal. **Required:** detect the new trust event for this handshake/server, durably save it, and return a non-secret connected-view notice identifying automatic post-expiry replacement; test that normal same-key renewal is not mislabelled and that the replacement notice survives the initial connected render.

5. **MEDIUM — The scan's “previous catalogue preserved on failure” claim is not atomic across catalogue and stable-identity updates.** `Store::snapshot` commits the legacy catalogue first and only then inserts stable identities in a separate transaction (`crates/chill-domain/src/store.rs:307-311`; first commit at `crates/chill-catalog/src/database.rs:815-842`). If identity persistence fails after the first commit, the scan is reported as failed and the UI says the previous catalogue was preserved (`crates/chill-server/src/catalog_api.rs:160-169`), although availability/new catalogue rows have already changed and new rows may be unreadable through `profile_view`. **Required:** stage/validate identities and commit catalogue plus identity mapping atomically in the same SQLite transaction, or implement a proven compensating rollback and truthful status. Add a fault-injection test between catalogue write and identity write that verifies the exact prior catalogue, last-scan marker, and identity map remain unchanged.

## Positive scoped observations

- The Tauri ingress is one serde-tagged, `deny_unknown_fields` command; JS cannot supply raw HTTP paths, headers, or filesystem paths. Redirects/proxies are disabled and JSON responses are capped.
- Profile rename uses expected revision and distinguishes stale (`409`) from absent (`404`) at the API seam. Catalogue pages are capped at 100 with `LIMIT + 1`; the UI requests 50. Watched/rating routes carry an explicit profile and the store validates profile/media identities.
- Scan launch is single-flight, freezes the configured root under a consistent `library → scan` lock order, returns immediately, bounds child output/time, and uses `kill_on_drop`. Root changes are refused while `running`; worker traversal aborts on partial I/O and does not touch NAS content.
- Original `ui/` sources remain present. The connected UI truthfully labels the native player and seasonal ambience as future work.
