# ADR-0021 — Plusieurs emplacements de bibliothèque, contrat additif

16octobre2026, IMPLEMENTED_DETAIL, auteur `/root`. Autorité : demande explicite de plusieurs localisations et de compatibilité avec le web. Complète ADR0002/0008/0011 ; aucune exposition réseau supplémentaire.

Conserver `video_root` comme emplacement principal et ajouter `additional_video_roots`, tableau facultatif. Omission/null conserve les emplacements supplémentaires ; tableau vide les retire. Le client natif n'envoie pas le nouveau champ lorsqu'il utilise encore le contrat historique, car les anciens serveurs refusent les champs inconnus. Les bases2026-10-14 etv1 ne changent pas. Au plus16 emplacements absolus dédiés, sans doublons ou chevauchement ; aucune création de dossier, montage, écriture ou modification de vidéo par ces réglages.

Les identifiants indexés principaux restent inchangés. Les autres ont un préfixe virtuel réservé `.chillcenter-locations/<sha256-racine>/`, indépendant de l'ordre des emplacements, jamais interprété comme un chemin physique de lecture. `Media.path` interne reste le chemin indexé absolu existant ; API et miroir exposent les identifiants/chemins relatifs déjà autorisés. Lecture et empreintes choisissent la racine propriétaire puis conservent les contrôles par descripteurs et révision de bibliothèque. Une mutation de configuration révoque les baux comme auparavant.

Un scan séquentiel rassemble les candidats avant une seule publication : échec d'une source = ancien catalogue intégral conservé. Budgets globaux300s/64Mio/200000 médias, pas multipliés par le nombre de racines. La sauvegarde locale refuse de traiter comme données locales une partie de ces emplacements. Les archives anciennes du principal restent importables ; des identifiants multi-emplacements exigent un mapping explicite non encore disponible et sont refusés, y compris si la destination n'a qu'un emplacement. Ne pas réinterpréter silencieusement ce préfixe sous la racine principale.

Conséquences : ajout de champs dans `library.json`, sans migration des UUID ou de la base source. Un ancien binaire à désérialisation fermée exige de restaurer son ancien fichier de réglages pour un rollback ; sauvegarde privée de la configuration avant toute future mise à jour matérielle. Aucun déploiement Pi ou web implicite. Preuves et limites : [lot Configuration](../../implementation/CONFIGURATION-MATCHING-20261016.md).
